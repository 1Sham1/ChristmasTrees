# План устранения предупреждений и ошибок

## Сводка

Проект: Android-приложение «Christmas Trees» (Kotlin, Jetpack Compose, Osmdroid)
Сборка: `BUILD SUCCESSFUL` — но обнаружено **27 проблем** (8 HIGH, 10 MEDIUM, 9 LOW)

---

## Фаза 1: Критические ошибки (HIGH) — утечки памяти и краши

### 1.1 SnowfallOverlay.kt — бесконечные `while(true)` циклы (memory leak)

**Файл:** `app/src/main/java/com/example/christmastrees/ui/components/SnowfallOverlay.kt`

**Проблема:** `while(true)` цикл дрейфа никогда не завершается, `fallJob.cancel()` после него недостижим.

**Решение:**
- Заменить `while(true)` + `delay()` на `snapshotFlow { sf.driftValues }` с `collect` в `LaunchedEffect`
- Использовать `repeatWhileLaunched` или `animateFloatAsState` для дрейфа
- Добавить `cancelKey = DisposableEffect(Unit) { onDispose { fallJob.cancel() } }`
- Объединить 15 `LaunchedEffect` в один с list of `AnimationVector2D`

**Ключевые строки:** drift loop + `fallJob.cancel()` после `while(true)`

---

### 1.2 MapScreen.kt — MapView не DISPOSING (memory leak)

**Файл:** `app/src/main/java/com/example/christmastrees/ui/screens/MapScreen.kt`

**Проблема:** `MapView` (osmdroid) создаётся в `AndroidView.factory`, но не вызывается `onDestroy()`/`onDetach()` при уничтожении.

**Решение:**
- Добавить `DisposableEffect` внутри `AndroidView` для вызова `mapView.onDestroy()`, `mapView.onDetach()`
- Освободить `ScaleGestureDetector` в `onDispose`
- Пример:
```kotlin
DisposableEffect(Unit) {
    onDispose {
        mapView.onDestroy()
        mapView.onDetach()
    }
}
```

---

### 1.3 MapScreen.kt — Handler callbacks после disposal

**Файл:** `app/src/main/java/com/example/christmastrees/ui/screens/MapScreen.kt`

**Проблема:** `Handler(Looper.getMainLooper()).post { }` внутри `LaunchedEffect` может выполниться после dispose.

**Решение:**
- Заменить `Handler.post` на прямые вызовы внутри `AndroidView.update` блока
- Использовать `LaunchedEffect` с `key` для реактивного обновления map overlays
- Удалить все `Handler(Looper.getMainLooper()).post` вызовы

---

### 1.4 MapScreen.kt — Full map rebuild + Bitmap GC pressure

**Файл:** `app/src/main/java/com/example/christmastrees/ui/screens/MapScreen.kt`

**Проблема:** Каждый раз при изменении маркеров удаляются ВСЕ оверлеи и создаются новые Bitmap.

**Решение:**
- Кэшировать Bitmap для каждого типа маркера через `remember` + `mutableMapOf`
- Использовать `snapshotFlow { viewModel.markers }` для реактивного обновления
- Обновлять/добавлять/удалять оверлеи точечно, а не перестраивать всё
- Кэшировать `createEmojiMarkerBitmap` по типу + размеру

---

### 1.5 MarkersViewModel.kt — `MarkerSize.valueOf()` краш на corrupted data

**Файл:** `app/src/main/java/com/example/christmastrees/viewmodel/MarkersViewModel.kt`

**Проблема:** `MarkerSize.valueOf(size)` бросает `IllegalArgumentException` при невалидном string.

**Решение:**
```kotlin
fun markerSize(): MarkerSize = MarkerSize.entries.find { it.name == size } ?: MarkerSize.MEDIUM
```
- Добавить безопасный парсинг с fallback
- Аналогично для `MarkerType.fromString` — добавить логирование при fallback

---

### 1.6 MarkersViewModel.kt — `computeCounts` fragile logic

**Файл:** `app/src/main/java/com/example/christmastrees/viewmodel/MarkersViewModel.kt`

**Проблема:** Логика `tSmallAcc / 10` непонятна и может давать неверные результаты.

**Решение:**
- Переписать с ясной семантикой: посчитать каждый тип отдельно
- Добавить комментарии с формулами
- Если это агрегация для статистики — сделать unit-тест

---

### 1.7 AudioManager.get() — краш при отсутствии init

**Файлы:** `app/src/main/java/com/example/christmastrees/util/AudioManager.kt`, `MainActivity.kt`

**Проблема:** `AudioManager.get()` бросает `IllegalStateException` если `init()` не вызван.

**Решение:**
- Добавить lazy initialization или null-safe accessor
- В `MainActivity` обернуть в `try/catch` или использовать `?` с fallback
- Убедиться что `MainApplication.onCreate()` вызывает `init()` до первой композиции

## Верификация

1. **`./gradlew assembleDebug`** — сборка должна проходить без ошибок
2. **`./gradlew assembleDebug --info 2>&1 | grep -i warning`** — проверить предупреждения компилятора
3. **Android Lint:** `./gradlew lintDebug` — проверить на проблемы с кодом
4. **Manual testing:**
   - Открыть/закрыть экран с картой (проверить memory leak через Android Profiler)
   - Включить/выключить снегопад несколько раз (проверить что корутины cancel)
   - Добавить/удалить маркеры (проверить что нет full rebuild)
   - Переключить музыку (проверить что не крашится при recomposition)
5. **ProGuard release build:** `./gradlew assembleRelease` — проверить что минификация работает
